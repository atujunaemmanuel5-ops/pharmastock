# PharmaStock AI — Forecast Evaluation

## 1. Overview

This document describes the evaluation of the sales forecasting component of PharmaStock AI.

The purpose of the evaluation is to compare three forecasting baselines and identify which performs best on historical sales data for each product group.

The forecasting component uses historical daily sales to generate predictions. These predictions can later support inventory planning and reorder recommendations when combined with appropriate inventory information.

**Important:** The dataset contains historical sales for eight product groups, not individual medicines. It does not contain actual inventory balances or recorded stock-out events.

## 3. Forecasting Methodology

Three baseline forecasting methods were implemented and compared.

### 3.1 Naive Forecast

The naive forecasting method uses the last observed training value as the prediction for every day in the test period.

If the last training observation is \(y_T\), the forecast is:

\[
\hat{y}_{T+h} = y_T
\]

where \(h\) represents the forecast horizon.

This method provides a simple benchmark against which more sophisticated forecasting approaches can be compared.

### 3.2 Seven-Day Moving Average

The moving-average method calculates the mean of the previous seven values to produce the next prediction.

The forecast is calculated as:

\[
\hat{y}_{T+1} =
\frac{1}{7}
\sum_{i=0}^{6} y_{T-i}
\]

For subsequent forecast steps, the implementation appends each prediction to the history and uses the latest seven values to calculate the next prediction.

During the 180-day evaluation, the method therefore uses its own previous predictions rather than actual values from the test period.

This approach avoids using future test observations to generate predictions.

### 3.3 Seven-Day Seasonal Naive

The seasonal-naive method repeats the pattern of the final observed training week.

It uses a seasonal period of seven days, representing a weekly cycle.

The implementation repeats the final seven observed values and then continues repeating the resulting pattern throughout the test horizon.

This method provides a baseline for examining whether repeating recent weekly sales patterns is useful for forecasting.

## 4. Training and Testing Strategy

The dataset was divided chronologically for each product group.

Random splitting was not used because it could allow observations from later dates to enter the training set while earlier dates appear in the test set.

Such a split would not accurately represent the task of predicting future sales from historical information.

### Split configuration

| Property | Value |
|---|---|
| Training observations per group | 1,925 |
| Testing observations per group | 180 |
| Training period | 2014-01-02 to 2019-04-10 |
| Testing period | 2019-04-11 to 2019-10-07 |

Each product group was evaluated separately.

The three forecasting methods were compared using the same test period for each group.

The evaluation therefore contains:

\[
8 \text{ groups} \times 3 \text{ methods}
= 24 \text{ comparisons}
\]

## 5. Evaluation Metrics

Two metrics were used to measure forecast accuracy: Mean Absolute Error (MAE) and Root Mean Squared Error (RMSE).

### 5.1 Mean Absolute Error (MAE)

MAE measures the average absolute difference between actual values and predicted values.

\[
MAE =
\frac{1}{n}
\sum_{i=1}^{n}
|y_i-\hat{y}_i|
\]

Where:

- \(n\) is the number of test observations.
- \(y_i\) is the actual sales quantity.
- \(\hat{y}_i\) is the predicted sales quantity.

A lower MAE indicates that predictions are closer to actual values on average.

MAE is expressed in the same quantity units as the target variable.

### 5.2 Root Mean Squared Error (RMSE)

RMSE is calculated by squaring the prediction errors, calculating their mean, and taking the square root.

\[
RMSE =
\sqrt{
\frac{1}{n}
\sum_{i=1}^{n}
(y_i-\hat{y}_i)^2
}
\]

RMSE penalises larger errors more heavily than MAE.

A lower RMSE indicates better performance according to this metric.

Both metrics were used because they provide complementary information about forecast errors.

MAPE was not used because some observations in the dataset have zero sales, making percentage-error calculations problematic.

### Interpretation

The seven-day moving average achieved the lowest MAE among the three tested methods for all eight product groups.

It also achieved the lowest RMSE for all eight groups.

These findings indicate that, on this test period and under the implemented forecasting procedures, the moving-average baseline outperformed the naive and seasonal-naive baselines.

However, this does not establish that it will always be the most accurate method. Its performance may change with different datasets, evaluation periods, or forecasting horizons.

N02BE had the largest MAE and RMSE among the selected best-performing methods. This suggests that its forecasts have larger absolute errors than those for the other groups. Further analysis would be needed to investigate the underlying sales patterns and sources of error.

N05C had the lowest MAE and RMSE among the selected best-performing methods.

These results should be interpreted relative to each product group's sales scale. Absolute errors are not directly comparable as percentages of demand across groups with different sales volumes.

## 8. Future Forecast Generation

After evaluating the three methods, the pipeline generates seven-day sales forecasts for each product group using the seven-day moving-average baseline.

The forecasts are saved to:

`data/forecasts/weekly_sales_forecast.csv`

The output contains the following columns:

| Column | Description |
|---|---|
| `sale_date` | Forecast date |
| `product_group` | Product group being forecast |
| `predicted_quantity` | Predicted sales quantity |
| `forecast_method` | Method used to generate the prediction |

The forecast horizon is seven days.

Since the final observation in the processed dataset is dated 2019-10-07, the generated forecast dates are 2019-10-08 through 2019-10-14.

**These dates reflect the historical dataset, not the current calendar date.** The predictions should therefore be treated as historical-data-based demonstration outputs, not current pharmacy demand forecasts.

The pipeline produces 56 forecast rows:

\[
8 \text{ groups} \times 7 \text{ days}
= 56 \text{ forecasts}
\]

## 10. Limitations

Several limitations must be considered when interpreting the results.

### 10.1 Historical dataset

The processed dataset ends on 2019-10-07.

The generated forecasts are therefore based on historical observations and should not be presented as current predictions of pharmacy demand.

More recent observations would be required for forecasts relevant to present-day operations.

### 10.2 Product-group granularity

The dataset contains eight product groups rather than individual medicine records.

The current model cannot generate separate forecasts for individual medicines within those groups.

### 10.3 No actual inventory records

The dataset does not provide actual inventory balances, supplier lead times, or recorded stock-out events.

Consequently, the forecasting component alone cannot establish whether a particular medicine will run out of stock.

### 10.4 Baseline methods only

The three methods are simple baselines.

More advanced approaches could be investigated later, but their usefulness should be established through appropriate evaluation rather than assumed.

### 10.5 Forecasting horizon

The historical evaluation uses a 180-day test period, while the future forecasting function generates seven-day predictions.

Performance over a long horizon may differ from performance over a short horizon. The current results should not be interpreted as proof of equivalent accuracy at every forecast horizon.

### 10.6 Inventory assumptions

Any stock-out or reorder recommendations developed from this component must use clearly identified inventory inputs.

If simulated inventory values are used during development or demonstration, they must be labelled as simulated rather than actual pharmacy records.

## 11. Conclusion

The forecasting component of PharmaStock AI successfully implements three baseline forecasting methods, evaluates their accuracy using MAE and RMSE, and generates seven-day forecasts for eight product groups.

On the selected historical test period, the seven-day moving average achieved the lowest MAE and RMSE for all eight product groups.

The evaluation results and generated forecasts are saved as CSV files for use by other components of the application.

The next development step is to connect the sales forecasts to an inventory component that accepts inventory quantities and relevant replenishment information.

This would allow the application to estimate stock coverage and potential replenishment needs. However, actual stock-out prediction would require appropriate inventory data and validation against real stock-out outcomes.

**Current status:** The baseline forecasting and evaluation pipeline is operational. Inventory risk estimation remains a separate development task.
